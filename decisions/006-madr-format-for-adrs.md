# ADR-006: MADR for Architecture Decision Records

## Status

Accepted — 2026-02-28

## Context

Need a format for recording architectural decisions that is:
- Readable by non-developers (CEO persona, legal team)
- Commit-friendly (plain Markdown)
- Minimal but structured

Options considered:
1. **MADR** (Markdown Any Decision Record)
2. **Nygard format** (original ADR format)
3. **Y-statements** (brief one-liner format)

## Decision

Use **MADR** format for all ADRs.

## Rationale

- **Readable**: Clear sections (Context, Decision, Rationale, Consequences)
- **Commit-friendly**: Plain Markdown, diffs are clean
- **Non-developer friendly**: No code required, CEO/legal can read and provide input
- **Flexible**: Optional sections for alternatives, related decisions, etc.

## Consequences

- **Positive**: Consistent format across the ecosystem
- **Positive**: Generated by `firm_adr_generate` tool
